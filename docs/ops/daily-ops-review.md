# Daily Ops Review Contract

Purpose: read `normalized-ops-state/v1` from Agent Work Receipts and produce a short, evidence-backed daily action list for Tom/Flip. This is a contract/template, not an automated scheduler and not a dashboard UI.

## Input

A normalized ops-state JSON generated by:

```bash
pnpm tsx scripts/ops/collect-agent-receipts.mjs <receipts-dir> <output-json>
```

Required sections:

- `NOW`
- `NEEDS_TOM`
- `BUILDING`
- `WAITING_OR_BLOCKED`
- `CHANGED`
- `STALE_OR_UNVERIFIED`

## Output shape

Emit concise markdown or JSON with these Tom-native categories:

1. `NEEDS_TOM` — owner decisions, credentials, access grants, budget calls, or priority calls.
2. `BUILDING` — active work lanes that should keep moving today.
3. `BLOCKED` — work waiting on a non-Tom dependency or failed verification.
4. `STALE_OR_DRIFTING` — self-reported, stale, unverified, or evidence-light work that should be verified or killed.
5. `SHIP_READY` — verified work with changed files and passing evidence that can be merged, handed off, or promoted.

For each recommended action include:

- category
- receipt id
- action
- evidence snippets from activity, diff summary, commands, blockers, and changed files
- whether the underlying receipt is live, sample, stale, or self-reported

## Ranking rules

1. Put real `NEEDS_TOM` items first, but do not over-ask Tom for non-owner blockers.
2. Put verified ship-ready work before speculative expansion.
3. Put blocked work before generic building status when a decision can unblock multiple lanes.
4. Call out `self_reported`, `stale`, and missing verification explicitly.
5. Prefer evidence from commands and changed files over prose status.

## Prompt template

```text
You are Flip running Tom's Daily Ops Review.
Read the normalized ops-state JSON below.
Return the top 4-6 actions for today using only these categories:
NEEDS_TOM, BUILDING, BLOCKED, STALE_OR_DRIFTING, SHIP_READY.

Rules:
- Use Tom-native category names exactly; do not use Dream branding.
- Treat sample, self_reported, stale, and unverified receipts as non-live until verified.
- Every action must cite receipt_id plus at least one evidence snippet.
- Do not call external APIs or mutate Paperclip, Linear, git, cron, gateway, Hermes profile, or messaging config.
- If evidence is weak, recommend verification rather than claiming progress.

Normalized ops-state JSON:
<PASTE_JSON_HERE>
```
